# writing-pm-prd

> 面向产品经理的 Claude Code Skill，用于撰写高质量、结构化的产品需求文档（PRD）。

## 背景

在日常产品工作中，PRD 是产品从「概念化」进入「图纸化」阶段的核心文档。一份好的 PRD 能显著减少跨角色沟通成本，确保设计、前端、后端、测试等协作方对需求有一致理解。然而，撰写 PRD 时常见的痛点包括：

- **结构不统一**：不同 PM 写出的文档格式各异，团队难以建立阅读默契
- **遗漏异常场景**：缺乏系统性的异常情况覆盖，测试环节频繁补充边界 Case
- **范围蔓延**：没有明确的 In/Out Scope 定义，需求越做越多
- **缺少 Why Now**：功能优先级缺乏时间维度的论证，容易在资源会上被挑战
- **AI 产品无适配**：传统 PRD 模版难以应对 AI/Agent 类产品的三元交互特性

本 Skill 融合 **本人和腾讯系产品经理的PRD 最佳实践** 与用户定制需求，提供一套适合我这类型产品经理的标准化、可裁剪的 PRD 撰写框架。

## 功能详情

### 核心能力

| 能力 | 说明 |
|------|------|
| **13 章节结构化模版** | 从文档信息、需求背景、问题定义、Why Now、范围边界，到业务流程、功能清单、需求描述、原型页面、数据埋点、非功能需求、风险依赖、附录，完整覆盖 |
| **双场景输出** | 支持 **飞书在线文档**（DocxXML 格式）和 **本地 Markdown 文件** 两种输出模式，对话中随时切换 |
| **飞书生态集成** | 选择飞书文档模式时，自动创建飞书文档 → 关联 OKR 记录 → 归档知识库，形成需求资产闭环 |
| **优先级驱动** | 所有功能点标注 P0/P1/P2，支撑团队在资源紧张时做 MVP 裁剪决策 |
| **异常情况必覆盖** | 每个功能点系统性地覆盖未登录、网络异常、数据为空、权限不足、操作失败等 5 类典型异常 |
| **一句话总结前置** | 每个功能描述以加粗的一句话总结开头，让读者 3 秒判断「这部分跟我有没有关系」 |

### PRD 模版章节

```
一、文档信息          → 版本、产品名、编写人、修订记录、项目成员
二、需求背景          → 背景概述、需求来源、目标用户角色、产品目标
三、需求问题是什么    → 核心问题陈述、用户痛点、解决思路概述
四、为什么是现在处理  → 时机分析、与其他机会的权衡、不处理的后果
五、需求范围与边界    → In Scope / Out of Scope（含原因）、假设与约束
六、业务流程/流程图   → 核心流程（Mermaid 图）、异常流程
七、功能清单          → 功能模块 | 功能点 | 细分功能点 | 功能描述 | 优先级
八、需求描述（核心）  → 一句话总结 → 用户场景 → 前置条件 → 流程说明 → 交互说明 → 异常处理
九、原型页面/UI页面   → 页面清单、跳转关系、关键页面原型说明
十、数据埋点与指标    → 成功指标、埋点事件表
十一、非功能需求      → 性能、兼容性、安全需求
十二、风险与依赖      → 风险矩阵（概率×影响）、外部依赖
十三、附录            → 相关文档、术语表、评审记录
```

### 适用产品类型

| 产品类型 | 专项适配 |
|----------|----------|
| **移动端 App** | 手势交互说明、转场动画描述、iOS/Android 版本兼容 |
| **小程序** | 微信平台能力限制（包大小、API）、基础库版本 |
| **Web 端** | 响应式布局、浏览器兼容性、SEO 考量 |
| **SaaS** | 多租户数据隔离、RBAC 权限模型、计费/定价影响 |
| **平台工具** | API 接口设计、开发者体验、向后兼容性 |

### 面向不同读者的内容侧重

- **设计师**：背景目标概述、用户画像、原型描述
- **前端工程师**：交互说明、状态处理、转场动画、埋点需求
- **后端工程师**：功能清单、数据关系、异常处理、接口逻辑
- **测试工程师**：功能清单、每个功能点的交互/规则/异常详情
- **运营人员**：背景、成功指标、功能价值

## 限制

- **飞书文档模式依赖飞书生态**：需要安装并认证 `lark-cli`，需以用户身份登录（`lark-cli auth login`）。Bot 身份无法创建归属于用户个人空间的文档
- **飞书 Token 有效期短**：用户 Token 通常 1-2 周过期，需定期重新授权。过期后只能使用 Bot 身份，无法写入个人文档
- **原型页面为文字描述**：模版的「原型页面」章节提供的是页面结构和交互的文字描述，非可视化原型。如需交互原型，建议配合 Figma/蓝湖链接使用
- **不覆盖技术实现细节**：本 Skill 输出的是产品需求文档，不包含技术方案设计、数据库 Schema、接口定义等技术实现层内容。这些应由技术 Spec 文档承接
- **依 AI 模型能力而定**：PRD 质量取决于当前使用的 AI 模型。复杂的领域知识、行业术语建议人工补充审核
- **Mermaid 流程图渲染**：Markdown 中的 Mermaid 流程图需要在支持 Mermaid 渲染的平台上查看（如 GitHub、飞书文档、Typora），纯文本编辑器无法渲染


### 撰写原则

本 Skill 遵循以下优先级高于模版细节的核心原则：

1. **结论先行**：每个章节先给总结再分点
2. **从宏观到微观**：先总体（流程、清单、架构）再细节
3. **异常情况必覆盖**：区分初级 PM 和资深 PM 的关键标志
4. **范围边界清晰**：明确「不做什么」比明确「做什么」更有助于防止范围蔓延
5. **以读者为中心**：PRD 是给别人看的，不是给自己看的

### 与同类 Skill 的对比

| 维度 | writing-pm-prd | writing-prds（内置） |
|------|----------------|---------------------|
| 模版结构 | 13 章节固定框架 | 多流派哲学参考（无固定格式） |
| 输出格式 | 飞书文档 + Markdown 双模式 | 仅对话式输出 |
| 飞书集成 | 文档创建 + OKR 关联 + 知识库归档 | 无 |
| 产品类型适配 | 5 类产品专项调整 | 通用 |
| 腾讯 PM 框架 | 融合 | 不涉及 |
